# 남강 GREEN MAP · 제품 명세 반영

## 범위
평거동 비로그인 주민이 활동 유형으로 후보를 찾고 상세 정보와 카카오맵 연결로 방문을 준비하는 React 모바일 웹. 데이터 담당자는 JSON과 근거 자료를 교체한다. 계정·DB·커뮤니티·관리자 서버는 제외한다. 모바일, 태블릿, 데스크톱 웹을 지원한다.

## 핵심 흐름
지도/목록 → 활동 유형 필터 또는 주소·이름 검색 → 매장 상세 → 카카오맵.

주요 필터는 다회용기, 자원순환, 제로웨이스트·리필, 친환경 교통·에너지. 보고서의 다른 활동을 보존하기 위해 플라스틱 줄이기·친환경제품·전자영수증·수리·포인트 분류도 제공한다. 제로웨이스트·리필은 현재 등록 근거가 없어 결과 0개. 친환경 교통·에너지는 자전거 업체 후보 2곳만 해당하며 에너지 활동이 확인된 것은 아니다.

## 신뢰성
첨부 보고서의 후보 12개만 유지. 전체 현장 검증 전이며 운영·실천·혜택을 확정하지 않는다. 자료가 없는 유형은 빈 상태, 키가 없는 지도는 준비 중 상태. 좌표 출처와 유효한 위경도가 있는 매장만 지도 핀을 만든다. 등록되지 않은 매장, 활동, 인증, 할인, 감축량을 생성하지 않는다.

## 카카오맵
Leaflet/OpenStreetMap을 카카오 JavaScript SDK로 교체했다. 필요한 값은 `VITE_KAKAO_MAP_APP_KEY`. Kakao Developers에서 지도 사용을 활성화하고 실제 서비스 도메인을 등록해야 한다. JavaScript 브라우저 키만 사용하고 REST API 키나 Admin 키를 넣지 않는다. `.env.example` 참고. Vite 시작 및 빌드 시 주입하므로 변경 후 재시작·재빌드한다.

좌표가 있으면 `https://map.kakao.com/link/to/이름,위도,경도`로 길찾기를 연결한다. 현재 좌표가 없어 길찾기 버튼은 위치 미제공 안내를 표시한다. 별도의 카카오맵에서 찾기 버튼으로 주소 검색을 제공한다. 주소만으로 목적지를 확정했다고 표현하지 않는다.

키 없음, SDK 실패·시간 초과, 재시도 상태를 구분한다. 필터가 바뀌면 이전 마커와 클릭 핸들러를 정리하고 새 결과만 표시한다. 모바일 지도/목록 전환 시 ResizeObserver로 지도 크기를 갱신한다.

## 데이터 교체 절차
1. 보고서 원문과 기준일 확인.
2. `src/data/stores.json` 수정. 필수 필드와 출처·검증 상태를 누락하지 않는다. 수선집을 교통 분류로 임의 확장하지 않는다.
3. 매장 좌표는 유효 범위 및 `coordinateSource`가 있어야 사용된다. 좌표가 없는 데이터는 null 유지.
4. `npm test`, `npm run build`, 브라우저 핵심 시나리오 실행.
5. 자료가 전혀 없으면 JSON을 `[]`로 교체할 수 있다. 임의 매장을 넣지 않는다. 안내의 보고서 기준일과 설명 문구도 실제 자료에 맞춰 갱신한다.

## 성공 지표와 검증
후속 출시 검증 지표: 상세 진입 비율, 필터 사용률, 길찾기 연결률, 조회 완료율, 모바일 로딩 시간. 현재 외부 분석 도구·사용자 추적은 추가하지 않았다. 실사용 수치를 측정했다고 주장하지 않는다. 데이터 일치·필수 필드 누락·임의 생성 여부는 자료 검토와 테스트로 확인한다.

## 남은 외부 조건
현재 카카오 키가 제공되지 않아 실제 지도 표시와 실제 카카오 API 권한을 검증하지 못했다. 키·허용 도메인·서비스 도메인 설정 후 실연동 검증이 필요하다. 후보 12개의 좌표 및 현장 운영·혜택은 별도 조사 과제다. 환경 초안은 저장할 수 있지만 게시를 수행하지 않는다.
