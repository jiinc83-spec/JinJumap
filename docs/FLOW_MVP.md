# 첨부 흐름도 기반 MVP

첨부된 두 장의 흐름도를 화면 전환 기준으로 삼았다. 기존 보고서 후보 12개와 근거 정보는 보존했으며, 좌표나 현장 검증 정보를 새로 만들지 않았다.

| 흐름도 단계 | 구현 동작 |
| --- | --- |
| 모바일 웹 최초 진입 | 탐색 화면, 활동 필터, 지도/목록 선택 |
| 지도 로딩 성공 | 카카오맵과 좌표 출처가 확인된 후보 마커 |
| 지도 로딩 실패 | 실패 안내와 다시 시도. 목록은 계속 이용 가능 |
| 지도 설정 전 | 준비 중 화면. 키 없음은 통신 실패와 구분 |
| 매장 데이터 없음 | 조사자료 준비 중. 대체 매장을 생성하지 않음 |
| 활동 유형 선택 | 목록과 지도 마커에 같은 결과 적용 |
| 필터 결과 없음 | 빈 결과와 필터 초기화 |
| 유효한 마커·목록 선택 | 동일한 매장의 상세 화면 |
| 잘못된 매장 선택·주소 | 매장 없음 안내와 목록 복귀 |
| 상세 정보 | 기본 정보, 실천·참여 방법, 포인트, 출처·검증 상태 |
| 길찾기 위치 있음 | 카카오맵 목적지 링크를 새 창으로 연결 |
| 길찾기 위치 없음 | 위치 미제공 안내. 주소 검색은 별도 버튼 |
| 연결 창 열기 실패 | 팝업 차단·연결 창 실패 안내 및 재시도 |

## 실행

```sh
cd /workspace/JinJumap
npm ci
npm run dev -- --port 5173
```

카카오 지도를 실제 표시하려면 `.env.example`을 참고해 JavaScript 키와 Kakao Developers 서비스 도메인을 설정해야 한다. 현재 모든 후보의 좌표가 없어 실제 매장 마커 및 바로 길찾기는 제공되지 않는다. 주소 검색을 통해 매장을 확인할 수 있다.

## 검증 범위

프로덕션 빌드와 데이터 검사를 수행했다. 모바일·데스크톱 브라우저 테스트에는 검색, 빈 데이터·필터, 상세·출처, 잘못된 ID 복구, 길찾기 위치 미제공, 팝업 차단·재시도를 포함한다. 지도 로딩 실패→재시도, 필터 마커 제거 및 마커→상세 연결은 테스트용 SDK 응답과 테스트 데이터로 검사한다. 테스트 좌표는 브라우저 테스트 응답에만 존재하며 실제 매장 데이터에 저장하지 않는다.

외부 카카오 서비스의 장애·길찾기 결과는 교차 출처 제약상 이 앱에서 판정할 수 없다. 실제 SDK 권한·지도 표시 및 외부 경로 결과의 검증은 키 설정 후 필요하다. 창이 열렸다는 사실을 길찾기 성공으로 표시하지 않는다. 자동 게시하지 않는다.
